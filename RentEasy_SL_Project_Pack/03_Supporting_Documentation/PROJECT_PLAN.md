# Project Plan and Work Breakdown Structure

| Work package | Activities | Dependency | Evidence / output |
|---|---|---|---|
| 1. Initiation | Confirm team, supervisor, project title and scope | None | Approved proposal |
| 2. Research | Stakeholder interviews, process review, literature/background research | 1 | Research log and findings |
| 3. Requirements | Functional/non-functional requirements, use cases, acceptance criteria | 2 | SRS |
| 4. Analysis/design | DFDs, ERD, data dictionary, architecture, UI mockups | 3 | Design pack |
| 5. Build foundation | Local environment, database, authentication, role access | 4 | Running base app |
| 6. Property module | Listings, images, search, moderation | 5 | Demonstrable listing workflow |
| 7. Tenant workflows | Favourites, viewings, applications, maintenance | 6 | Workflow evidence |
| 8. Testing | Functional, validation, access control, responsive checks | 7 | Test register and defects |
| 9. Documentation | Report, user manual, technical notes, references | 8 | Final report and manual |
| 10. Presentation | Slides, demo script, Q&A rehearsal | 9 | Presentation pack |

## Suggested 7-week execution plan (adapt to official Week 11 deadline)
- Week 1: approval, team responsibilities and stakeholder access.
- Week 2: research, interviews and requirements baseline.
- Week 3: diagrams, database and interface design.
- Week 4: authentication, roles, property submission and moderation.
- Week 5: search, favourites, viewing and application workflows.
- Week 6: maintenance, testing, bug fixes and deployment rehearsal.
- Week 7: report finalisation, user manual and live presentation rehearsal.

## Change control
Every scope change should record request, reason, impact on schedule, affected requirements/diagrams/code, approval and version. Keep a baseline of the approved requirements.
