RENTEASY SL - COMPLETE PROJECT PACK
===================================

MAIN DOCUMENT
-------------
docs/RentEasy_SL_Complete_Project_Blueprint.docx

A comprehensive project specification and design guide for RentEasy SL:
- Product definition, problem statement, objectives and scope
- User roles, permissions and detailed feature catalogue
- MVP versus phase-two feature priorities
- Tenant, landlord, agent and administrator workflows
- Brand/logo concept and visual design guidance
- Six interface mockups
- PHP + Laravel + MySQL technology stack and application architecture
- Suggested Laravel folder structure and example routes
- Conceptual ERD, Data Dictionary, DFD Level 0 and DFD Level 1
- Use Case overview and detailed use case descriptions
- Security, privacy, validation and anti-fraud considerations
- Week 4 to Week 11 project plan, testing plan, risk register and submission checklist

TECHNOLOGY DECISION
-------------------
The proposed backend is PHP using Laravel, with MySQL as the relational database.
Python and FastAPI are not part of this proposed stack. The frontend direction is
Laravel Blade with Bootstrap or a consistent custom CSS system and light JavaScript.

IMPORTANT NOTES
---------------
1. This pack is a planning blueprint, not completed software or completed research.
   The team must conduct genuine interviews, validate the problem and requirements,
   implement the system, execute tests and record actual results.
2. Property names and prices in the UI mockups are sample data for illustration only.
   They are not real property offers or verified market prices.
3. A RentEasy listing review badge must not be described as a legal title guarantee,
   government verification or guarantee that a property is free from disputes.
4. The recommended student MVP records rent entries; it does not collect, hold or
   transfer users' money. Payment gateway integration is a later, separately assessed
   feature.
5. The uploaded COMP 318 brief gives Week 11 as the submission deadline. Confirm the
   exact calendar date with the lecturer. The brief also contains conflicting 50% and
   60% module-weighting references; ask the lecturer which applies.
6. Follow the lecturer's formatting instructions for the final submission report:
   Tahoma, 12 pt, 1.5 line spacing and justified alignment, with the university cover
   page and printed submission as required.
